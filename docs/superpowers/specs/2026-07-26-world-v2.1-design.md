# 世界 v2.1 设计：生产经济与目标认知

**日期：** 2026-07-26 · **状态：** 已与项目所有者确认，待转实施计划
**定位变更：** 项目目标由"验证进化能否产生可感差异"扩展为"建一个有经济、有道德、有历史的 AI 生命世界"（所有者 2026-07-26 决定，选项 B）。冻结的 1C 预注册与官方运行成为**那个小世界**的历史记录，仍然有效、仍可引用，但不再是新世界的闸门。§17.1 路线图待重画。

---

## 1. 为什么做这件事

根因诊断（docs/idle-convergence-diagnosis.md）确定：**这个世界里"守在会重生的灌木旁等着"是真正的最优策略**，因为价值在固定地点随时间累积，而随机方向的探索没有信息收益。进化找到了它，世界因此变安静（终局 idle 611‰，2/12 seed 越过 800‰ 静止线）。

世界 v2.1 的核心设计原则由此导出：

> **让价值来自「组合」，而不是来自「等待」。**

配套的第二条原则来自诊断的另一半（`explore` 是闭眼随机走一步）：

> **让「知道东西在哪」成为需要维护、可以出错、可以传承的知识。**

## 2. 范围

**本 spec 交付**：多资源地理、背包与配方、建筑、目标层认知、空间记忆及其继承与误传、繁殖扩展、纪事扩展、runner 指标扩展、两项校准。

**明确不做**（各自后续 spec）：
- 社交需求、赠予/分享（V2.2）
- 偷窃、暴力、声誉、七宗罪命名（V2.3）
- 航海、考古、多地点（V2.4，依赖阶段二 World Protocol）
- **种田**——它是"守着等"的完美形态（作物在固定地块定时成熟），现在加进来会加深根因问题；等 V2.2 有了"照料"机制（不管就绝收）再放回来
- 31 情境套件重写与四臂手工原型重配——依赖本 spec 的目标空间落定，单独立项

## 3. 资源地理

网格 32×32 → **64×64**，视野半径仍为 **8**。这个比例是设计的承重墙：**看不见整张地图，记忆才有价值。**

地图划分为 **4×4 = 16 个区域**（每区 16×16），按类型分配区域，保证空间分离：

| 资源 | 区域数 | 每区站点数 | 总站点 | 容量 | 夏/冬再生 ppm |
|---|---|---|---|---|---|
| 浆果（灌木） | 8 | 3 | 24 | 5 | 60_000 / 5_000 |
| 木材（林地） | 4 | 2 | 8 | 8 | 8_000 / 2_000 |
| 石料（采石场） | 2 | 2 | 4 | 20 | 20_000 / 20_000 |
| 黄金（金脉） | 2 | 1 | 2 | 3 | 500 / 500 |

区域到类型的分配与区域内站点坐标均由 `drawInt(seedRoot, …, "site-*", …)` 确定性生成，写入 manifest（因此进哈希、可重放）。

一次 `gather` 动作产出 **1 单位**，与资源类型无关——差异来自站点数量、容量、再生速度与**路程**。

## 4. 背包、配方、建筑

**背包**：`NpcState.carry: Record<ResourceKind, number>`，四类合计上限 **CARRY_CAP = 10**。原 `berries: number` 字段由 `carry.berry` 取代。

背包上限看着琐碎，其实是破"守着等"的机械保证：**配方需求量超过一次背得动的量，所以必须往返。**

| 建筑 | 配方 | 作用 |
|---|---|---|
| 庇护所 shelter | 木 4 + 石 2 | 冬季避寒。**开局世界没有任何庇护所**——manifest 不再预置，第一个冬天是真危机 |
| 粮仓 granary | 木 6 + 石 4 | 储存超出背包上限的浆果（GRANARY_CAP = 50） |
| 纪念碑 monument | 金 3 + 石 7 | **没有任何生存收益**，只被写进纪事 |

纪念碑配方恰好等于背包上限 10（金 3 + 石 7）⟨2026-07-27 更正：初稿写作金 3 + 石 8 = 11，超过 CARRY_CAP，纪念碑将永远无法建成，等于静默废掉本机制；实现期由 Task 6 发现⟩——**盖一座碑要正好背满一整包对的材料**，而黄金只有 2 个站点、再生 500ppm，因此纪念碑天然稀有。

纪念碑是有意的设计：它制造一个真实的道德张力——**饥荒年月里，把劳力花在纪念碑还是粮食上**。这是 V2.3（骄傲、贪婪）最好的土壤，而且它现在就能产出好故事。

**建筑归属**：`ownerNpcId` + `ownerLineageId` 自建成起记录。粮仓的存取权限按 **`ownerLineageId`** 判定而非个人 ⟨自审改正⟩——否则建造者一死粮仓即成孤儿，而"家族粮仓传给后代"既更合逻辑也更有故事。V2.3 的侵犯与守护将复用这两个字段。

**冬季避寒规则变更**：`winterColdHpDrain` 仅在 NPC **不在任何庇护所** 时施加（原为不在 manifest 预置庇护所时）。庇护所不限归属——避寒是公共品，屯粮不是。

## 5. 动作集

| 动作 | 前置 | 效果 |
|---|---|---|
| `move` | 目标格在界内 | 移动 1 格（不变） |
| `gather {siteId}` | 站点距离 ≤1、存量 >0、背包未满 | 背包 +1，站点存量 −1 |
| `consume` | `carry.berry > 0` | 吃 1 颗，能量 +`berryEnergy` |
| `deposit {buildingId}` | 站在**本脉**粮仓上 | 背包浆果转入粮仓（受 GRANARY_CAP 限制） |
| `withdraw {buildingId}` | 站在**本脉**粮仓上 | 反向，受背包上限限制 |
| `build {kind}` | 站在空格、背包含完整配方 | 扣料，在当前格生成建筑 |
| `idle` | — | 无操作 |
| `flee` | 反射层 | 远离狼（不变） |

原 `take` 动作由 `gather` 取代。

## 6. 认知：目标层 + 空间记忆

现有三层（反射 → 效用 → Resolver）保留，但**效用层的裁决对象从「动作」升级为「目标」**，动作由确定性规划器展开。

### 6.1 目标集（封闭键集）

`GOAL_KEYS = ["eat", "stockpile", "takeShelter", "shelterBuild", "granaryBuild", "monumentBuild", "rest"]`

`PolicyS.utilityWeights` → `PolicyS.goalWeights: Record<GoalKey, Milli>`。封闭键集纪律不变：**进化改数值，永不改键**。

打分（全整数）：

| 目标 | 分数 | 门控 |
|---|---|---|
| eat | `floor(w.eat × hungerNeed / 1000)` | — |
| stockpile | `floor(w.stockpile × (1000 − foodSecurity) / 1000)`，`foodSecurity = min(1000, (carry.berry + 本脉粮仓浆果) × 100)` | — |
| takeShelter | `w.takeShelter − 15 × 记忆中最近庇护所距离` | 冬季、且当前不在庇护所上、且记忆中有庇护所 |
| shelterBuild | `w.shelterBuild` | 记忆中不存在距当前位置 ≤ `SHELTER_NEED_RADIUS = 12` 的庇护所 |
| granaryBuild | `w.granaryBuild` | 本脉无粮仓 |
| monumentBuild | `w.monumentBuild` | **无门控**——它必须能与生存竞争，这正是设计意图 |
| rest | `w.rest` | — |

**关于 takeShelter 与 shelterBuild 的分工**（自审补正）：庇护所是**公共品**（避寒不看归属），若 `shelterBuild` 门控成"世界上还没有庇护所"，则第一个建成后全族再无人建造，而 25 个 NPC 挤一格显然不成立。改为**按距离门控**：NPC 想在自己活动的地方附近有庇护所，因此会在地图各处形成分散的聚居点。而"冬天跑去庇护所躲"是另一件事，由 `takeShelter` 承担——旧世界的 `shelter` 效用键对应的正是这个行为，目标集初稿漏掉了它，NPC 会一边追求采集一边冻死。

`rest` 是原 `idle` 键的对应物，保留它使"什么都不做"仍可表达；但它现在必须战胜的是**有明确路径的建造目标**，而不是一个闭眼随机走的 explore。

### 6.2 承诺与迟滞

`NpcState.goal: { key: GoalKey; sinceTick: number } | null`。每 tick 重算分数，但**只有当最高分超过当前目标分数 + `commitmentThreshold` 时才切换**；当前目标已满足或已失效（如配方所需站点全空）时立即释放。

`commitmentThreshold` 是可进化的策略字段（类似现有 `deliberationEpsilon`），创始范围 150 ± 100。

**这一条是可读性的来源**：有了它，观察者才能说"她花了三天搬石头"，而不是看着一个每 tick 改主意的抽风机。

### 6.3 规划器（纯函数）

`plan(goal, obs, memory, manifest) → Action`：

- **eat**：背包有果 → `consume`；站在本脉粮仓且仓内有果 → `withdraw`；否则取记忆中最近的浆果站点 → 相邻且有存量则 `gather`，否则 `move` 靠近；记忆为空 → 探索步（`drawInt` 抽方向）
- **stockpile**：同 eat 的采集路径，但采到背包满，然后前往本脉粮仓 `deposit`（本脉无粮仓时该目标失效，让位给 granaryBuild）
- **takeShelter**：记忆中最近的庇护所 → `move` 靠近；已在其上则 `idle`（避寒生效）
- **shelterBuild / granaryBuild / monumentBuild**：计算配方缺口 → 依次补齐缺口最大的资源（平手按 `RESOURCE_KINDS` 顺序）→ 取记忆中该类型最近站点 → `gather`/`move`；配方齐备后，当前格为空则 `build`，否则 `move` 到最近空格
- **rest**：`idle`

规划器无状态、无随机（除记忆为空时的探索步，使用键控 `drawInt`），因此可重放。

### 6.4 空间记忆

```
MemoryEntry = { kind: ResourceKind | BuildingKind; pos: Vec2; lastStock: number; seenTick: number; ownerLineageId: string | null }
```

**建筑也进记忆**（自审补正；`ownerLineageId` 为 2026-07-27 实现期的设计更正——建筑条目须记住归属，否则"本脉是否已有粮仓"只能靠视野判断，NPC 一走远就会重复建造粮仓、且背满货找不到家，两者都会人为制造活动量并污染 §11 的 C2 测量）：冬季避寒改为"必须站在庇护所上"后，NPC 必须**记得庇护所在哪**才能跑去躲；`shelterBuild` 的距离门控同样要查记忆。建筑条目的 `lastStock` 恒为 1（存在标记）。

- `MEMORY_CAP = 12`。每 tick，视野内站点与建筑以**真实存量**插入或刷新。
- 淘汰：满时丢弃 `seenTick` 最旧的一条（平手按 pos 再 kind 的确定性序）。
- **不做存量衰减估算**：记忆里存的是"上次看到的数字"，NPC 抵达后才发现真相——**这正是戏剧性所在**。规划器跳过 `lastStock === 0` 的条目；若全部为 0 或记忆为空，则转探索步。抵达后刷新为 0，自动纠错，不会死循环。
- **继承**：出生时从亲本 A 继承最近见到的至多 `MEMORY_INHERIT_MAX = 6` 条；每条以 `MEMORY_MISREMEMBER_PPM = 100_000`（10%）的概率被**误传**——位置抖动 ±2 格（键控 `drawInt`）。

误传是设计而非缺陷：**记错位置的后代会真的白跑一趟甚至饿死**。这把文化层从"抽象态度的误传"升级成"关于世界的知识的误传"，戏剧性强得多，而且完全可审计。

## 7. 繁殖扩展

`breed()` 增加：`goalWeights` 逐键交叉与有界变异（沿用现有 identity/policy 的 ppm 与 jitter 常数）、`commitmentThreshold`（沿用 epsilon 的 jitter 口径）、以及 §6.4 的记忆继承。信念（文化层 effect）机制不变，`EFFECT_TARGETS` 迁移为新目标键（`w:eat`/`w:stockpile`/`w:takeShelter`/`w:shelterBuild`/`w:granaryBuild`/`w:monumentBuild`/`w:rest`/`t:hungerUrgent`）。三条既有信念形成规则按语义重映射 ⟨自审明确化⟩：狼袭 → `w:takeShelter`、饥饿 → `w:eat`、冬季转换 → `w:takeShelter`（winter 条件）。**不新增规则**（YAGNI）。

## 8. 纪事扩展

新增 SemanticEvent：`building_built { kind, ownerNpcId, pos }`。传记模板增加对应句式；纪念碑单独成句（它是无收益建筑，最值得被记载）。血脉纪事的"结语"沿用现有双路径（产品端漂移结语 / 评审包中性结语）。

## 9. Runner 与指标扩展

`FormalSnapshot` 增加：目标直方图（各 GoalKey 被选中的份额 ×1000）、建筑计数（按 kind）、资源总存量（按 kind）。动作直方图保留。行动日志事件增加 `goal` 字段（审计：能回答"它当时在干什么"）。

## 10. 不变量（不可让渡）

整数运算、`drawInt` 键控随机、无浮点、`src/` 下无 `Date.now`/`Math.random`、canonical JSON 哈希、行动日志哈希链、checkpoint、重放与 `--strict` 严格校验——**全部不变**。目标与规划状态、背包、记忆、建筑均进 `NpcState`/`WorldState`，因此进哈希。规划器为纯函数。

**这是项目最值钱的资产，不能为了富世界丢掉。**

## 11. 两项校准（实施计划必须包含）

**C1 首冬存续校准。** 开局无庇护所、创始 NPC 记忆为空，第一个冬天（tick 400）可能整族覆灭。可调旋钮（按此优先级）：创始 NPC 预置记忆条数（"他们在这里长大"）、首个夏季长度、`winterColdHpDrain`。**通过判据：≥8/12 pilot seed 在第一个冬天结束时仍有 ≥10 个存活个体。** 首冬必须是真危机，但不能是必然的灭绝。

**C2 根因验证（本设计的核心检验）。** 用现有 formal runner 跑 pilot seeds × 60k tick，观测 idle/rest 份额轨迹。**预测：终局 rest 份额显著低于小世界的 611‰，且不呈单调爬升。** 若仍然爬升，说明 NPC 找到了新的"守着等"均衡（例如停在两个站点之间），必须在扩展 V2.2 之前重新诊断——**这一条是防止我们把同一个错误建得更大的闸门。**
